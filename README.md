# Tour API

Сервис для получения публичных предложений Talisman Tour: каталог, горящие туры, поиск по параметрам и JSON-карточки для публикации. Работает отдельно от сайта-источника. Данные Tourvisor собираются после обычной загрузки публичных страниц в Chromium.

## Запуск на Windows

Нужен Python 3.12 или новее. Из папки проекта в PowerShell:

```powershell
./setup.ps1
./start.ps1
```

Откройте [документацию API](http://127.0.0.1:8000/docs). Пока процесс работает, он автоматически получает данные. Первый сбор занимает время: состояние смотрите в `GET /api/status`. До первой успешной загрузки соответствующий раздел возвращает 503.

Если запуск скриптов PowerShell запрещён вашей настройкой, выполните команды напрямую:

```powershell
py -m venv .venv
./.venv/Scripts/python.exe -m pip install -r requirements.txt
./.venv/Scripts/python.exe -m playwright install chromium
./.venv/Scripts/python.exe -m tour_api serve
```

Linux: создайте окружение `python -m venv .venv`, используйте `.venv/bin/python` вместо Windows-пути, установите браузер командой `python -m playwright install --with-deps chromium`.

## Подключение другого сайта

Ваш сайт обращается к этому API и оформляет полученные карточки самостоятельно. Для постоянно доступного внешнего адреса запустите сервис на своём сервере с HTTPS. Локальный адрес доступен только на компьютере, где работает программа.

Задайте длинный случайный ключ через переменную `TOUR_API_KEY`. Клиент передаёт его в заголовке `X-API-Key`. Храните ключ на сервере вашего сайта. Для браузерного клиента можно задать точные разрешённые адреса через `TOUR_CORS_ORIGINS`; CORS не скрывает ключ, встроенный в браузерный код.

```powershell
$env:TOUR_API_KEY = 'ВАШ_СЛУЧАЙНЫЙ_СЕКРЕТНЫЙ_КЛЮЧ'
$env:TOUR_CORS_ORIGINS = 'https://ваш-сайт.example'
./.venv/Scripts/python.exe -m tour_api serve --host 0.0.0.0 --port 8000
```

Для Docker включён Dockerfile. Контейнер ожидает `TOUR_API_KEY` и постоянный том в `/data`. Docker-сборка в рамках локальной проверки не выполнялась.

## Методы

| Метод | Назначение |
|---|---|
| `GET /health` | Доступность процесса и наличие первоначальных данных |
| `GET /api/status` | Число записей, время обновлений и ошибки источника |
| `GET /api/countries` | Справочник стран из раздела сайта; доступность вылетов определяется формой поиска |
| `GET /api/tours` | Опубликованный каталог с ценами «от» |
| `GET /api/hot-tours` | Показанные на странице горящие предложения |
| `GET /api/tours/{id}` | Одна карточка каталога или горящего тура |
| `GET /api/hotels` | Описания отелей, накопленные успешными поисками |
| `GET /api/publications?source=hot` | Карточки и текст для публикации горящих туров |
| `GET /api/publications?source=catalogue` | Карточки каталога для публикации |
| `POST /api/search` | Поставить поиск в очередь |
| `GET /api/search/{id}` | Статус и результаты поиска |
| `GET /api/search/{id}/publications` | Результаты конкретного поиска с текстами для публикации |
| `POST /api/refresh?kind=all` | Запросить обновление; также доступны `hot`, `catalogue`, `countries` |

Каталог, горящие туры и публикации поддерживают `q`, `country`, `currency`, `min_price`, `max_price`, `limit`, `offset`. Для фильтра цены обязательна валюта. Число записей в одном ответе — от 1 до 100. Записи без цены не проходят числовой фильтр. Страна каталога может быть не указана источником: для таких карточек используйте текстовый фильтр `q`.

Примеры:

```text
/api/hot-tours?country=Турция&currency=EUR&max_price=700&limit=20
/api/tours?q=Дубай
/api/publications?source=hot&currency=USD&max_price=600
```

## Поиск

Создайте запрос с будущими датами. Например, на Python:

```python
from datetime import date, timedelta
import time
import requests

base = 'http://127.0.0.1:8000'
headers = {}  # При настроенном ключе: {'X-API-Key': 'ваш ключ'}
start = date.today() + timedelta(days=7)
request = {
    'departure': 'Ташкент',
    'country': 'Турция',
    'date_from': start.isoformat(),
    'date_to': (start + timedelta(days=3)).isoformat(),
    'nights_from': 7,
    'nights_to': 7,
    'adults': 2,
    'children': [],
    'limit': 15
}
response = requests.post(base + '/api/search', json=request, headers=headers)
response.raise_for_status()
job = response.json()
for _ in range(120):
    response = requests.get(base + job['status_url'], headers=headers)
    response.raise_for_status()
    result = response.json()
    if result['status'] in ('complete', 'failed'):
        break
    time.sleep(3)
print(result)
```

`requests` нужен только для этого примера клиента; установите его отдельно или используйте Swagger в `/docs`.

Поиск выполняется последовательно в одном браузерном работнике. Очередь ограничена тремя запросами; при переполнении возвращается 429. Сам сбор имеет ограничение по времени. Одинаковый успешный запрос может использовать результат не старше пяти минут (`cached: true`).

Форма источника сейчас показывает вылеты из Ташкента и Самарканда. Названия страны и города должны соответствовать её вариантам. Диапазон дат — максимум 30 дней, горизонт — год. Точный возраст ребёнка в текущей форме выбирается от 2 до 15 лет. Значения 0–1 и 16–17 не подменяются другим возрастом: поиск завершится понятной ошибкой. Длительность сверх доступных значений формы также не подменяется.

Результат — первая загруженная порция минимальных цен по отелям, до указанного `limit`, с `truncated: true`. Это не полный перебор базы всех туроператоров. Точная дата конкретного предложения и число ночей могут отсутствовать на сводной карточке; в таком случае возвращается null, а параметры выполненного поиска сохраняются отдельно в `search`.

## Обновления и значения полей

- Горящие предложения обновляются каждые 30 минут, каталог и страны — раз в 6 часов, пока сервис запущен.
- `TOUR_HOT_INTERVAL` и `TOUR_CATALOGUE_INTERVAL` задают интервалы в секундах. Минимумы — 300 и 3600 секунд.
- `TOUR_AUTO_REFRESH=0` отключает автоматическое обновление. Ручная команда: `python -m tour_api update`.
- `TOUR_DATA_DIR` задаёт папку SQLite; по умолчанию `data`.
- `fetched_at` — время получения в UTC, а не время изменения цены поставщиком.
- `stale: true` означает просроченный снимок или ошибку последнего обновления. Последние успешные записи сохраняются при сбоях.
- Результаты поиска помечаются `stale: true` через 5 минут. У каждого отеля есть собственный `stale`; обновление других отелей не освежает старые записи. Порог для описаний — два интервала каталога.
- История завершённых поисков хранится не более суток и ограничена 1000 записями. Настройки: `TOUR_JOB_RETENTION_SECONDS` (минимум 3600) и `TOUR_MAX_SAVED_JOBS` (минимум 10). Очистка происходит при запуске и записи поисков. Удалённый поиск возвращает 404.
- `price_basis` — `per_person`, `total` или `unknown`. Валюты не смешиваются и не конвертируются.
- Для каталога валюта может браться из структурированных данных самого сайта. Исходное обозначение «у.е.» остаётся в `price.raw`.
- Даты без года в горящих карточках сохраняются как `date_text`; `departure_date` остаётся null, чтобы не угадывать год.
- `images` содержит ссылки источника. Фотографии не скачиваются и не копируются на ваш сервер автоматически.
- `publication_status: draft` означает подготовленную карточку. API ничего не публикует в социальных сетях или на другом сайте самостоятельно.
- Описание каталога — текст карточки; описание отеля — текст показанной поисковой карточки. Полные статьи, все номера отеля и все фотографии не гарантируются.

## Проверка

```powershell
./.venv/Scripts/python.exe -m pip install -r requirements-dev.txt
./.venv/Scripts/python.exe -m pytest -q
```

Тесты проверяют разбор карточек, валюты и базу цены, сохранение данных при сбое, параметры поиска, доступ по ключу, фильтры и экспорт. Реальное выполнение поиска зависит от работоспособности источника. При изменении разметки или ограничении доступа адаптер может потребовать обновления; ошибки не заменяются выдуманными результатами.
